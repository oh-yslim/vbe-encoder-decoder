✓ Files stay in your browser   ✓ Native-compatible byte downloads for tested files   ✓ Windows compatibility tested separately

1. Input

Files are read using BOM/Unicode checks and guarded legacy-code-page detection. Ambiguous file encodings are rejected rather than silently misdecoded. VBE decoding additionally checks strict legacy-byte interpretations only when the displayed Unicode text fails integrity checks. For unedited uploaded files, the result retains the detected source file encoding and BOM. Pasted or edited input uses ASCII / UTF-16 LE with BOM automatically.

Download encoding: ASCII (when the input is ASCII-only), otherwise UTF-16 LE with BOM.

2. Result

Text is never executed

Result download encoding: —

Choose Encode or Decode.

VBE is obfuscation, not encryption. Never execute scripts from untrusted sources.

Pasted or edited text exports: ASCII when all characters are U+0000–U+007F; UTF-16 LE with BOM otherwise, including Unicode in comments. Unedited uploaded sources follow the original file format and native-compatible byte rules. Some native 8-bit VBE files are not valid UTF-8; download the exact bytes rather than copying the escaped preview. Download Input preserves original upload bytes.

Diagnostic decoding can display unverified text even if length, checksum, or recovered-control checks fail. An automatic legacy-byte interpretation is accepted only when length, checksum, and recovered control checks pass unambiguously. Unverified downloads require explicit acknowledgement. Validation does not execute VBScript or guarantee Windows Script Host compatibility. BOM-less legacy files may have an undetectable or ambiguous code page.
